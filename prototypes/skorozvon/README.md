# Локальный прототип Скорозвона

## Настоящий виджет — локальный стенд, 25.11.2026

По подтверждённому поручению пользователя добавлена отдельная страница с настоящим SDK. Предыдущий синтетический прототип на4178 сохранён.

```sh
node prototypes/skorozvon/serve-live.mjs
# http://127.0.0.1:4179/
node tests/sk-widget-live.mjs
```

1. Откройте страницу и сохраните локальную тестовую карточку с точным `external_id` тестового контакта Скорозвона. Имя/город нужны только для локального отображения. Никакой загрузки клиентов или чтения рабочей CRM нет.
2. «Открыть панель Скорозвона» загружает официальный `https://widget.skorozvon.ru/phone.js`. Появится собственная форма входа поставщика. Войдите тестовым оператором; не вводите общий административный ключ в код/репозиторий.
3. Статус, проект, управление звонком и результат доступны в штатной панели. Звонок из карточки выполняется только по нажатию «Позвонить через СК». Для ручного теста запустите сервер с согласованным номером в переменной окружения `SK_WIDGET_TEST_PHONE` в формате +7 и десять цифр. Без неё панель работает, а кнопка выключена. Значение не сохраняется в репозитории или журнале.
4. Четыре документированных события открывают карточку по `lead_external_id`. Неизвестный ID очищает отображение прежнего клиента. Пока идёт звонок, редактирование сопоставления заблокировано; события другого одновременного звонка показывают предупреждение без смены карточки. Запоздалые события уже завершённого звонка игнорируются.
5. Сохраняйте итог через панель поставщика. `call:ended` не означает, что результат сохранён. Серверного webhook/создания заказов на этом локальном стенде нет.
6. Завершите разговор и сохраните результат перед выходом. Используйте выход в панели Скорозвона: закрытие вкладки само по себе не обещает выхода из аккаунта.

Для проверки двух вкладок войдите в обычный кабинет тестовым оператором на отдельном тестовом проекте. Отметьте статус и доступность телефонии. Войдите этим же оператором в локальную панель, проверьте статус в стандартной вкладке и включённое скрытие номеров. Нажмите кнопку один раз. Проверьте звук в обе стороны, отображение телефона в панели и истории, сохраните результат. Затем проверьте, куда пришёл следующий вызов тестового проекта и сохранился ли статус оператора. Для обычной работы рекомендации вендора по активным вкладкам приведены ниже.

`serve-live.mjs` слушает только 127.0.0.1. GET /test-call сообщает только о наличии и использовании тестового номера. При явном нажатии кнопки POST /test-call выдаёт номер браузерному виджету один раз на процесс. Сбой или перезагрузка страницы не инициируют повторный звонок. Для набора нужен готовый виджет с включённым скрытием номеров. Полный телефон доступен в памяти браузера при вызове SDK. Параметры URL запрещены. Разрешения CSP для внешнего SDK действуют только на локальном стенде.

**Проверено:** загрузка реальногоSDK, форма входа иCORS-frame поставщика в браузере; сохранение локальной тестовой карточки; адаптивная ширина390px; синтетические тесты адаптера/сопоставления/запоздалых событий иHTTP-защит. **Пока не проверено:** вход тестового оператора, гарнитура/WebRTC, реальные события автообзвона и сохранение результата у поставщика. Внешние WebSocket/media origins после входа зависят от ответа поставщика; не расширятьCSP до любыхHTTPS/WSS при ошибке, сначала установить конкретный необходимый адрес.

Основа: официальныйPDF страницы61–62 и публичныйSDK, проверенный25.11.2026. ВSDK дополнительно подтверждены `canClose` и события `authorized`, `ready`, `unauthorized`; они не описаны на этих страницахPDF и потребуют повторной проверки при обновленииSDK. Vendor-код не копируется вGit. PR466 остаётсяDraft: не объединять вmain и не устанавливать наproduction.

## Предыдущий этап: только демонстрация

Прототип рабочего места оператора, 24.11.2026. Только вымышленные контакты и события. Это **не установленный виджет поставщика** и не доказательство работы WebRTC/автообзвона. Нет подключения к CRM, БД, native-телефонии или аккаунту Скорозвона. Сохранение результата и перевод имитируются; данные остаются в памяти вкладки до её закрытия/обновления.

## Запуск

Из корня репозитория (Node.js 22+), без установки зависимостей:

```sh
node prototypes/skorozvon/serve.mjs
# Открыть http://127.0.0.1:4178
node tests/sk-widget-prototype.mjs
```

Остановка: Ctrl+C. Другой локальный порт можно передать аргументом. Сервер слушает только 127.0.0.1; раздаёт четыре файла по allowlist. CSP запрещает сетевые соединения, внешние скрипты, фреймы и отправку форм; Permissions-Policy запрещает микрофон/камеру. В прототипе нет ввода ключей и режима включения реальных звонков.

## Проверяемые сценарии

1. «Начать демо-смену»: тестовый автообзвон, дозвон, разговор, карточка.
2. Удержание/возврат и имитация перевода сотруднику/группе.
3. Завершить, выбрать результат, комментарий и при необходимости будущее время перезвона по Москве.
4. Сохранить результат, получить следующий тестовый звонок. До сохранения новый звонок и переключение карточки заблокированы.
5. Ручной тестовый звонок из выбранной карточки; входящий и неизвестный контакт в «Других тестовых сценариях».
6. Неизвестный контакт не привязывается к предыдущей карточке. Повторное сохранение и запоздалое событие предыдущего звонка отклоняются.

## Граница следующего этапа

Официальная документация: https://app.skorozvon.ru/static/skorozvon/docs/SkorozvonAPI.pdf, страницы 61–62. SDK: `https://widget.skorozvon.ru/phone.js`, `Tube.Widgets.Phone`, `login({email, api_key})`, `makeCall`, `transferCurrent`. `bindDocumentedEvents` показывает подписку и снятие подписок на четыре документированных события Backbone; пока отдельно проверен синтетическим emitter и не соединён с SDK. Авторизация, загрузка SDK и реальные вызовы в этом прототипе не реализованы.

Для реального интеграционного стенда потребуются отдельно выбранная тестовая учётная запись и проект, сопоставление сотрудников и `lead_external_id`, проверка сессий/закрытия вкладки, гарнитуры и ограничений браузера. Общий административный ключ нельзя помещать в клиентский bundle. Пока не подтверждён API собственной формы результата/перезвона, сохранять через готовую панель поставщика, итог получать серверным webhook `call_result`. Здесь нет утверждения, что наша демонстрационная форма умеет записывать в Скорозвон.

Инструкция amoCRM подтверждает статусы, проектный обзвон, удержание и перевод: https://skorozvon.ru/manual/integratsii/amocrm/vidzhet-v-amocrm-2. Виджет нельзя считать идентичным по всем деталям до интеграционной проверки. По инструкции вкладку кабинета Скорозвона следует закрывать при приёме через виджет.
