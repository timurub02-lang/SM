# Временный обмен складом с LeadVertex

Настройки администратора: Настройки → Интеграции → Интеграция с ЛВ Склад.
Рабочий проект задаётся адресом *.leadvertex.ru и API-ключом администратора.
Документация: https://demo-1.leadvertex.ru/admin/page/api.html
Остатки: https://leadvertex.ru/knowledgebase/59-uchet-ostatkov-tovara

- getOfferGoods: каталог, used — активность, reserve — доступный остаток. Новые карточки создаются только для активных товаров. Уже связанные не удаляются.
- increaseGoodReserve / reduceGoodReserve: POST формы goodID, quantity, comment; подтверждение — { ID: "OK" }. В API нет документированного ключа идемпотентности.
- Только сервер хранит API-ключ. Админ управляет подключением и разрешением учитывать движения CRM. Операторам, руководителям и логистам изменение подключения недоступно.
- Заказ существует только в одной системе. Одинаковые названия сопоставляются; для разных названий админ явно выбирает соответствие до первого импорта. Название и данные СДЭК существующей карточки сохраняются.
- При связи фиксируется сумма прежних ручных движений CRM. Она не прибавляется к остатку ЛВ. Все текущие резервы и выкупы CRM учитываются при первой передаче.
- Доступно в CRM = последний остаток ЛВ + уже переданное потребление CRM + новые ручные движения CRM − все текущие резервы и выкупы CRM. Это исключает двойное вычитание собственных движений после обратного чтения из ЛВ.
- Локальный резерв действует сразу. Обмен — каждую минуту. Конкурирующая продажа в ЛВ между проверками всё ещё может привести к отрицательному остатку; общей транзакции между двумя системами API не предоставляет.
- Оплата меняет резерв на выкуп без второго уменьшения остатка. Отмена освобождает резерв; статус возврата сам по себе — нет, нужен фактический приём на склад.
- Изменения отправляются как разница по каждому товару. Операция сохраняется до запроса. После подтверждения атомарно фиксируются результат и переданное количество. Отмена и создание до очередного обмена могут взаимно погаситься.
- Потерянный ответ или падение процесса после отправки — неизвестный результат, без слепого повтора. Новые резервы данного товара блокируются. Админ сверяет уникальный номер операции с историей ЛВ, фиксирует выполнено/не выполнено. Решение и сотрудник сохраняются.
- Выключение учёта CRM прекращает новые записи в ЛВ, но не откатывает уже выполненные. Повторное включение передаёт накопившуюся разницу. Отключение всего обмена замораживает входящий остаток; локальный учёт продолжается.
- После отказа от ЛВ: выключить обмен, сверить незавершённые операции, удалить подключение. Ключ удаляется; товары, последний остаток и история сохраняются. Будущие локальные движения продолжают менять остаток CRM.
- Фоновый запуск: scripts/sync-lv-warehouse.mjs, systemd sm-crm-lv-warehouse.timer. Общая блокировка не допускает одновременного ручного и фонового обмена.

Данные для СДЭК новых товаров необходимо проверить отдельно: закупочная цена ЛВ не подставляется как объявленная стоимость.
