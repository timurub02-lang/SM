# Замена телефона для СДЭК

Настройки → Интеграции → Замена телефона. Доступ администратора. Пул полностью отделён от исходящих номеров Билайн АТС; база запрещает пересечения.

Перед созданием отправления выделяется свободный номер с наименьшим числом закреплений. При равенстве выбирается раньше назначенный (никогда не назначенные — первыми). Повторная попытка с действующим закреплением сохраняет номер и счётчик. Ошибка/потерянный ответ СДЭК сохраняет закрепление; повторная отправка с неизвестным результатом блокируется до проверки UUID, как и раньше.

Для соединения выбирается один список разрешённых статусов CRM и СДЭК. Достаточно совпадения текущего статуса хотя бы одного источника. Нет совпадений — гудки 60 секунд без соединения. Снятие галочки действует на следующий звонок сразу после сохранения, без ожидания смены статуса; уже идущий разговор не прерывается. Правила освобождения остаются отдельными и имеют приоритет; само освобождение выполняется атомарно при изменении статуса заказа. Подтверждённое удаление из СДЭК обрабатывается как REMOVED, включая корректировки. Освобождённый номер сразу доступен следующему заказу; повторное выделение после освобождения — новое закрепление и новое использование.

Включённое соединение направляется на текущий основной телефон клиента. Администратор может сделать дополнительный номер основным в карточке клиента. При выключенном соединении — 60 секунд гудков и завершение. Свободный номер попадает в обычную обработку входящих, как раньше. История закреплений хранится после освобождения; интерфейс показывает последние 1000.

Нет свободных номеров: в СДЭК идёт реальный телефон, в отправлении появляется отметка. Сбой подмены/нет актуальной синхронизации АТС: выгрузка блокируется. Администратор получает задачу при остатке ниже порога (по умолчанию 500) или сбое. Выключение интеграции прекращает новые выделения; уже закреплённые номера продолжают обслуживать доставку.

## Новая АТС

Только новый сервер. `crm-replacement.py` синхронизирует отдельный пул через защищённый `/api/telephony/replacement`, сохраняет локальную копию и подтверждает её CRM. Без подтверждения новый номер не выделяется. Синхронизация запускается существующим загрузчиком результатов звонков. Входящий на закреплённый номер не создаёт обычное обращение; API определяет актуального клиента. При ошибке маршрутизации звонок завершается без соединения с другим получателем.

Установить crm-replacement.py рядом с crm-call.py, обновить оба диалплана и выполнить dialplan reload. Новые файлы и пул должны быть установлены до включения интеграции. Предварительно сделать резервные копии. Старая АТС не изменяется.

Лимит исходящих начал общий: 5 CPS. Для ёмкости доставка учитывается как два соединения из 25, обычный исходящий как одно. Фактический учёт входящих у оператора связи требует подтверждения. Длительность соединения ограничена 30 минутами, как рабочие звонки CRM.

Проверки: tests/phone-replacement.mjs, tests/phone-replacement-pbx.py, tests/telephony-http.mjs, tests/cdek-delete-http.mjs. Последние два запускаются после сборки Miran, используют только временные базы и имитатор СДЭК. Реальный тест оператора связи проводится отдельно.

## Запланировано для раздела «Выкуп»: подтверждённый курьер

При начале разработки раздела «Выкуп» напомнить об этом требовании. Это будущая функция, сейчас не реализована.

Добавить записи звонков на подменный номер. Сотрудник выкупа или главный логист прослушивает конкретный разговор, убеждается, что звонил курьер, и ставит отметку «Перезванивать курьеру». Получателем обратных звонков клиента закрепляется номер звонящего из выбранного разговора. После подтверждения новые звонки с других номеров, в том числе спам, не заменяют этого получателя.

Закрепление курьера действует только в пределах текущего закрепления подменного номера за заказом. При освобождении номера связь с курьером и отметка сбрасываются; следующему заказу они не передаются. Права на подтверждение уточнить при реализации раздела.

## Обратный звонок клиента

АТС передаёт определившийся номер звонящего в защищённый API. Если звонит основной или дополнительный телефон клиента текущего заказа, он соединяется с последним внешним звонящим этого закрепления. Звонки клиента не переписывают получателя обратного звонка. Если получатель ещё не известен — гудки 60 секунд, без звонка клиента самому себе. При скрытом номере звонящего соединение с клиентом возможно, но получателя обратного звонка запомнить нельзя.

Получатель запоминается при разрешённой попытке соединения с клиентом, даже если тот не ответил. Оба направления подчиняются текущим разрешённым статусам. Связь хранится по уникальному закреплению и удаляется при освобождении; при повторном использовании номера она не переносится. Звонки до установки этой возможности не восстанавливаются: для первого теста нужно снова позвонить клиенту через Б, затем клиент перезванивает на Б. Оба направления не создают обычных входящих обращений. Исходящий номер для обоих направлений — Б.
