# Native T1 recordings

The bridge captures native recordings while the operator is logged in, periodically and before a normal logout. Oktell 2.15 ignores personal journal requests for offline users. A one-use `gettemphttppass` authorizes the immediate HTTP download; the token is never returned to the browser or saved in a database. The existing `sync-base` job verifies the durable file through the private `/pilot-recording?chain=<uuid>` endpoint before marking CRM history. Install the matching bridge, including `recording-file.mjs`, before the runtime. Its service must have write access to `/var/lib/sm-crm/recordings`.

The bridge resolves only a completed, answered call and its exact commutation from the durable journal. Downloads use the commissioned private origin `http://10.21.103.2:4055/download/rec/`; redirects are disabled, with a 20-second timeout, a 32 MiB cap and WAV/MP3 signature validation. Files are atomically published outside releases before setting `phone_calls.recording`. The recording endpoint preserves CRM access checks and byte ranges for both formats.

`oktell-recording-health` reports pending and failed copies. Each run processes at most five calls; failed copies retry after 15 minutes without blocking the history cursor. If the connection is lost before capture, the recording waits for the operator's next session; background work never logs in a staff member automatically. Captured recordings remain available after logout. Native originals are not deleted. This copies the operator commutation; multi-leg transfer recording needs a separately tested design. The workstation-to-PBX media path still requires an authorized live test.

Separately install `scripts/backup-crm.py` as `/usr/local/sbin/backup-sm-crm` and the `sm-crm-backup` service/timer from `scripts/systemd`. Run and verify the service before enabling the timer. It takes consistent, integrity-checked copies of the CRM and bridge SQLite databases every day, retaining seven dated copies per database. These are local recovery copies, not protection against loss of the whole host; native SQL/audio and off-host backup remain separate. Restoring the two journals requires reconciling their history cursor, as documented in deployment.md.
