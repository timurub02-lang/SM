# Развёртывание CRM на Миране

Исходники: `https://github.com/timurub02-lang/SM`, ветка `main`.
VM: `crm`, адрес `10.20.0.10`, домен `https://crm.smanalytics.ru`.

Серверная версия собирается командой `CRM_RUNTIME=miran npx next build --webpack`.
Используется Node.js 24 и встроенный SQLite. Сборка Next.js заменяет модуль
`cloudflare:workers` локальным адаптером; локальная версия Sites продолжает работать с D1.

Данные находятся отдельно от кода: `/var/lib/sm-crm/crm.sqlite`.
`CRM_DATABASE_PATH=... node scripts/init-sqlite.mjs` создаёт схему пустой базы
или проверяет существующую. Нельзя копировать работающую SQLite-базу обычным
копированием: используйте SQLite backup API, который учитывает WAL.

Приложение слушает только `127.0.0.1:3000`. Nginx завершает HTTPS, проверяет
пароль владельца и заменяет заголовки пользователя и секрет доверенного прокси.
Переменные находятся в `/etc/sm-crm.env`, пароль nginx — в `/etc/nginx/crm.htpasswd`.
Эти файлы и базы никогда не добавляются в Git.

Это закрытый доступ владельца. Переключатель сотрудника в CRM не является
персональной учётной записью или разграничением доступа сотрудников.

Обновления: изменить проект → проверить типы, тест SQLite и сборку → commit/push
в GitHub → получить код в новый каталог релиза `/srv/crm/releases/<commit>` →
`npm ci` → собрать → скопировать `public` и `.next/static` в `.next/standalone` →
сохранить резервную копию базы → переключить `/srv/crm/current` → перезапустить
только `sm-crm.service` → проверить сайт и API. Предыдущий релиз сохранять для отката.
Простое обновление кода не должно заново инициализировать или очищать базу.

Проверки: `npx tsc --noEmit`, `node --experimental-strip-types tests/sqlite.mjs`.
Без пароля HTTPS должен отвечать 401; с паролем `/` и `/api/crm` — 200.
Проверять также запрет неподходящего Origin и подмены заголовков пользователя.
